# 整体代码审查与修复

收尾日期：2026-10-01。本地浏览器验证及后端测试于 2026-09-30 执行。

## 结论

检查范围包括前后端请求、AI 对话、地点选择、输入校验、来源状态、图表组件、部署配置及未使用代码。发现的具体问题已修复。此结果不代表所有规划功能已完成，也不保证不存在其他漏洞。

## 已修复问题

| 编号 | 级别 | 问题及影响 | 修复 |
| --- | --- | --- | --- |
| R1 | 高 | AI 限流使用可伪造的 X-Forwarded-For 首项，换请求头可绕过限制。 | AssistantController 使用连接来源地址；application.properties 禁用自动信任转发头。新增绕过回归测试。 |
| R2 | 中 | 聊天历史每条限制 1000 字符，较长模型回复使下一轮请求被拒绝。 | AssistantMessage 放宽到 8000 字符，前端同步限制历史；当前用户问题仍最多 1000 字符。 |
| R3 | 中 | 空历史/候选条目、负地点 ID 及过大候选序号可能导致异常。 | 增加输入约束、候选数量上限及序号溢出处理。 |
| R4 | 中 | 请求或响应正文停滞时，前端可能一直等待。 | 共享 fetchJson 设置常规请求 90 秒、AI 请求 240 秒截止，保留调用方取消；AI 界面区分限流、超时和服务不可用。 |
| R5 | 中 | 云量校验将当地时间分钟清零，非整小时时区被误判。 | AssistantService 保留当地 HH:mm，增加 Kathmandu 时区测试。 |
| R6 | 中 | 风暴预报刷新失败后仍可能保留旧预报、Kp 或预警。 | NextAuroraStormForecast 清除本次请求失败的数据。 |
| R7 | 低 | 地点搜索未避开输入法确认事件，加载时可重复提交。 | LocationSearch 检查输入法组合状态及加载状态。 |
| R8 | 低 | 主页面未将选中地点传给地图；夜晚详情样式仅在废弃页面导入。 | 补充地图属性，将样式导入放到 NightOutlookCard。 |

R1 的部署取舍：Render 代理后的多个访客可能共享限流桶，目前是保守的连接地址限制。应先核实可信代理链或接入身份认证，再实现可靠的逐用户限流。内存限流会随重启清空，不是分布式限流或费用硬上限。参考 [MDN 转发地址信任边界](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Forwarded-For)。

## 冗余清理
