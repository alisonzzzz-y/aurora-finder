# 07 区：地面观测验证数据候选

状态：已完成 cleaned CSV 本地质量审计；未纳入产品或等级规则。资料核对日期：2026-09-26。

## 候选来源：Aurorasaurus Web Observations

Zenodo 发布了 2014-08-01 至 2025-08-02 的 Aurorasaurus 网页观测 CSV，含 transformed 与 cleaned 两种文件，总大小约 16.8 MB。记录说明这是社区提交的极光目击观测数据，供科学研究使用。NASA 的项目介绍说明报告者可提交“看到”或“未看到”的观测。2026 年技术报告已在 Frontiers 发布，Aurorasaurus 的数据发布说明及官方清理 notebook 进一步概述了处理流程：transformed 数据会移除或遮盖垃圾、测试和个人信息；cleaned 数据还会排除持续超过 12 小时、`sky_id` 为 cloudy (`clou`) 或 bright (`brig`) 的记录，并处理重复报告。notebook 使用 `see_aurora` 区分看到/未看到，`time_start` 和 `time_end` 作为时间字段，`st_y`/`st_x` 作为地理纬度/经度输入来计算地磁坐标。时间筛选将 `time_start` 解析为 UTC。

该处理说明支持一个重要边界：清晰天空下明确提交的“未看到”可以作为候选负标签；没有报告仍然不是负标签。发布方也提醒，报告受观察视角、人口分布和光污染影响，报告地点并不等于极光实际所在的位置；数据在强地磁风暴期间尤其丰富。因此不能假定全时段、全球和地点覆盖均衡，也不能直接把记录比例解释为某地的观测概率。仍需直接核对实际 CSV 的列类型、空值、坐标精度和时间格式。notebook 将人工重复项复核标为可选，并注明仅对 2024 年 5 月 Gannon 风暴数据执行过；因此不能假设整个 cleaned 文件都经过相同的人工排重。发布流程文档没有给出本项目所需的空间/时间匹配误差。

## 本项目可用来回答什么

若最终使用许可与字段语义明确，这类数据可用于离线评估短时间、地点匹配下的模型信号是否与经质量控制的地面观测相符。它比用全球 Kp 标签更贴近地面观测，但不能单独推出未来整晚的等级：社区报告不是系统性巡天，负面样本的天空条件和参与者覆盖会影响结果，地点周边天气也必须按同一时间窗口匹配。

可先设计离线评估，不训练或部署模型：按地点、时间、日照/黑暗、云量、OVATION 和 Kp 形成可追溯样本；把明确的正向观测与符合条件的明确负向观测分开；按时间留出测试集，并按地区与风暴强弱报告样本量和误差。报告数量不足或标签条件不完整的样本仅用于描述，不参与阈值选择。

#### 建议的事件级留出流程

1. 先固定可追溯的历史 3 小时 Kp 来源与版本。GFZ 提供历史 Kp 下载；NOAA 说明 Kp ≥ 5 对应地磁风暴条件。来源、数据修订版和缺测处理要在计算观测结果前记录。
2. 仅从 Kp 时间序列构造事件 ID：以达到 Kp ≥ 5 的 3 小时段为事件核心，再用预先固定的静息间隔合并相邻核心段，并固定事件前后上下文窗口。静息间隔和上下文长度目前尚未选定，不能看过本地标签表现后再挑选。
3. 一个事件及其上下文内的所有报告、模型快照和天气样本都必须进入同一数据分区。按事件留出测试，不按报告行或 UTC 日期随机拆分；调参时也使用按事件分组的交叉验证。
4. 继续只把明确“看见”作为候选正标签，把明确“未看见且晴空”作为候选负标签；其余标签排除。候选重复签名在获得可靠人工复核前保留为敏感性分析，不静默删除。
5. 逐事件报告正负样本数、可匹配率、时间/空间缺测和评价指标。若独立留出事件或清晰负样本不足，就报告覆盖限制和探索性结果，不计算或宣传观测概率。

候选 Kp 事件窗口由脚本即时构造，但没有保存逐行事件 ID 或最终测试集。历史 OVATION 版本/时间覆盖、匹配范围、评价指标和事件间隔仍需确认；此前已查看 2025 年聚合标签，因此该候选时间切分不能再称为未触碰的独立测试。跨年份审计显示 2019–2021 年报告覆盖稀疏，且 2024–2025 年报告集中明显；事件分组不会消除这种代表性限制。重复签名字段与复核规则见 [Aurorasaurus 官方清理 notebook](https://github.com/aurorasaurus/Aurorasaurus_on_Jupyter/blob/main/2_data_cleaning.ipynb)。

### Kp 风暴事件覆盖与时间切分候选（2026-09-26）

从 GFZ Web Service API 下载了 definitive 3 小时 Kp 序列。响应元数据标记来源为 GFZ Potsdam、许可为 CC BY 4.0；共 32,160 个连续时段，覆盖 2014-08-01 00:00 UTC 至 2025-08-02 21:00 UTC，脚本未发现缺失或不规则时段。GFZ 说明 API 时间戳对应区间起点。来源页：[GFZ 数据/API 说明](https://kp.gfz.de/en/data)。NOAA 将 Kp ≥ 5 定义为地磁风暴条件：[NOAA Planetary K-index](https://www.spaceweather.gov/products/planetary-k-index)。

可复跑的数据下载和审计命令：

```sh
curl -L 'https://kp.gfz.de/app/json/?start=2014-08-01T00:00:00Z&end=2025-08-02T23:59:59Z&index=Kp&status=def' -o <kp-history.json>
python3 scripts/audit_kp_event_coverage.py \
  --observations <cleaned.csv> \
  --kp-json <kp-history.json> \
  --candidate-cutoff 2025-01-01T00:00:00Z
```

审计以 `Kp >= 5` 的三小时时段作为风暴核心，再按核心之间的安静间隔分组，并在每个分组两侧加入半个间隔长度的上下文。对 24/48/72 小时三种设置做了敏感性检查：

| 核心间隔合并阈值 | 两侧上下文 | 候选窗口数 | 同时有看见和晴空未看见 | 两类各至少 5 条* | 窗口内报告数 | 看见 / 晴空未看见 / 其他排除 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 24 小时 | 各 12 小时 | 230 | 136 | 56 | 14,971 | 12,070 / 2,067 / 834 |
| 48 小时 | 各 24 小时 | 213 | 144 | 69 | 16,099 | 12,714 / 2,416 / 969 |
| 72 小时 | 各 36 小时 | 197 | 143 | 69 | 16,880 | 13,177 / 2,613 / 1,090 |

*“每类至少 5 条”只是数量筛查，不能代表样本充足或结果有统计效力。报告行仍包含未人工确认的重复候选。

以 2025-01-01 00:00 UTC 为候选时间切点、采用 48 小时合并和两侧各 24 小时上下文时，切点前完整结束的 195 个窗口列为开发候选，跨越切点或位于其后的 18 个窗口整体列为测试候选；1 个跨年窗口整体放入测试侧。开发侧有 11,282 条看见、1,881 条晴空未看见及 836 条其他标签；测试侧有 1,432 条看见、535 条晴空未看见及 133 条其他标签。测试候选中 18 个窗口都有两类标签，14 个窗口每类至少 5 条。仍有 6,181 条报告在这些事件上下文之外；本审计没有把它们当作负样本或塞入任意一侧。

这提供了一个可复核的**时间切分候选**，但不是独立测试集：我们已经检查过这些年份的聚合标签数，且 2025 数据只覆盖到 8 月 2 日。不得用该候选集报告未见过的模型表现。候选窗口也不是官方命名的风暴 ID；分组间隔与上下文仍需在正式测试前固定。若要声称独立预测能力，需要未来未参与规则调整的新观测期或另外收集并锁定的样本。历史 OVATION 档案覆盖、逐点匹配规则、事件内的报告相关性及空间代表性仍待验证，因此这一步没有训练模型、调整等级阈值或计算概率。

脚本只读两份输入，打印聚合事件/标签计数，不导出逐条报告。原始 CSV 和 Kp JSON 都只保存在系统临时目录，未提交仓库。

### 2025 候选留出窗口的 OVATION 档案覆盖

为了进一步判断 2025 候选窗口是否有可用历史网格，审计了 NASA CCMC iSWA OVATION Prime 的 2024-12 至 2025-07 月目录。根据一个 2025-05-17 样例文件，网格坐标为 96 个 MLT 点（0–23.75 小时）和 80 个磁纬点（50–89.5 度），共 7,680 个点。CCMC 将模型分布描述为按磁地方时和磁纬分箱；样例文本没有提供已核实的输出单位。

按 GFZ Kp 生成 48 小时合并、前后各 24 小时上下文的事件窗口，并以 2025-01-01 为候选切点，18 个切点后窗口包含 2,100 条报告：1,432 条明确看见、535 条晴空未看见、133 条因天空状态未知或其他标签排除。1,045 条正负报告的磁纬坐标低于样例网格下界 50 度；不对这些点外推。其余 1,145 条中，1,042 条报告的最近 15 分钟时间快照名称能在官方月目录找到，103 条报告对应 42 个不同时间点的快照未列在目录中。

这只是**文件存在性和一个样例坐标轴的覆盖检查**。没有下载这些候选时间的历史网格值，没有把报告时间/位置映射到网格单元，也没有比较正负标签对应的模型输出。因此它不能证明模型区分了看到与未看到，也不能用于估计精确率、召回率、阈值、当地等级或概率。此前已检查候选留出窗口的汇总标签，所以这些窗口仍不是独立测试集。

复跑脚本：`scripts/audit_ovation_event_coverage.py`。参数需指向本地 cleaned CSV、GFZ Kp JSON、官方月目录 HTML 索引文件所在目录，以及一个已下载的 OVATION 三列样例网格。原始 CSV、Kp JSON、索引页面和网格样例仅在临时目录使用，不提交仓库。脚本只输出聚合计数，不输出逐条报告位置或标识。

## 当前结论

Aurorasaurus cleaned 文件已按用户决定用于本地离线质量审计和跨年份 OVATION 网格试配；原始文件未加入仓库或重新分发。数据发布页未填写 License，但本项目按用户决定继续进行非商业的本地验证。后续公开展示或重新发布原始记录仍需单独核对来源条款。候选正标签是明确报告看到极光，候选负标签仅是明确未看到且天空字段为 `clea`；天空状况未知的未看到报告排除。强烈的事件、地区和纬度覆盖偏差仍未解决；2016–2018 年历史模型档案还存在缺档。当前线上规则继续保持 `NOT_VALIDATED`，接口继续返回 `INSUFFICIENT_DATA`；没有生成极光概率或高、中、低观测等级。
